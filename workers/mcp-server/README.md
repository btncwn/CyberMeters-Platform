# CyberMeters MCP-03 local gateway

From this directory, run `npm ci`, `npm test`, and `npm run dry-run` for local validation. Install the locked `workers/scan-api` dependencies before the joint runtime test. No command here deploys a Worker.

The default entrypoint returns `503 {"error":"mcp_not_configured"}` unless `MCP_INTERNAL_ENABLED` is exactly `true` and `env.MCP_BACKEND` exposes `getWorkspaceSummary`. The Wrangler config declares a local service binding to `cybermeters-platform#McpReadService` but sets no enablement variable, route, production hostname, `workers.dev` URL, or preview URL. A request header alone cannot enable the gateway.

The enabled path accepts only exact `POST /mcp` on HTTP loopback with matching Host and, if sent, Origin. Wrangler sets `request.cf` on local requests, so that property is not a local-only signal. It requires an `Authorization: Bearer cm_<64 lowercase hex characters>` header before the MCP handler runs. The 74-character header cap rejects sessions, malformed tokens, and extra values. Token validity, expiry, workspace binding, current membership, rate limit, and awaited audit are the scan API entrypoint's responsibility on every RPC call. The gateway calls only `env.MCP_BACKEND.getWorkspaceSummary({ bearer, workspaceId })`; it does not use public HTTP or pass an AbortSignal over RPC. The bearer remains in a per-request closure and is stripped before the SDK sees the request. It is never included in metrics, errors, or projected output.

The existing `createLocalTestWorker` remains a fixture-only test path and accepts an injected backend with `getWorkspaceSummary({ workspaceId, signal })`. Run `node ../../scripts/validate-mcp-rpc-runtime.js` for the repeatable joint local two-Worker proof. It uses the real named RPC binding, a disposable local D1 database with two synthetic tenants, and no remote binding or production token. It checks tenant denials, the atomic budget, and durable success/denial audits. Backend denials carry only a generated request ID and fixed reason; malformed bearer values are rejected at the gateway before RPC and are not written to backend audit storage.

The MCP handler keeps strict input, host, origin, method, path, body and response caps, JSON-only stateless responses, legacy rejection, output field allowlists, and a two-second response deadline. An RPC already invoked may continue after that deadline; the backend must enforce its own limit and awaited audit policy. The gateway is not a substitute for backend authorization.

This is internal engineering trial code, not a customer endpoint. A future public hostname requires a separate explicit route and origin policy, OAuth and audience controls, deployed binding proof, tenant and audit tests, and release authorization. None is configured here.
