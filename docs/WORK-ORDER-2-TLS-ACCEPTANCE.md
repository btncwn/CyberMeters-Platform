# Work Order 2 — TLS acceptance ledger

Status: **incomplete / draft**. This ledger maps each requested control to its executable path and evidence. A passing local test does not authorize production use. Work Order 1 PR #598 merged on 13 October 2026; PR #599 now includes that `main` merge. `TLS_ASSESSMENT_MODE` is unset and the customer setting is hidden until the full acceptance review.

Production enablement and merge are withheld until the remaining acceptance items and final independent review are resolved. Findings must never interpret `uncertain`, `unexecutable`, `not_authorized` or a missing check as a clean result.

The 13 October Docker lab ran each 22-test suite under a one-CPU, 512 MiB container cap with networking disabled. Each suite completed in 2.16–2.31 seconds and measured 40 checks, 43 engine connections and 92,189 TLS wire bytes. The highest coarse `docker stats` sample during the repeated build-stage test load was 16.86 MiB and 82.96% of one CPU. The final runtime image was 361,885,971 bytes and its idle sample was 804 KiB. These are local lab measurements with different process mixes; they do not establish production collector peak memory, customer-scale throughput or Cloudflare container cost.
