# Read-only MCP beta: client compatibility

**Checked:** 15 October 2026. **Claim level:** bounded synthetic protocol reliability, not customer or named-client acceptance. Production customer MCP is disabled; staging was restored to `503 mcp_not_configured` after the latest three-window test. Six fresh synthetic grants passed OAuth DCR + PKCE, repeated read-only tool discovery, tenant isolation, revocation and audit through a test client. An earlier run failed at `tools/list`; its cause remains unknown and did not recur in this check. These runs did **not** connect Claude, ChatGPT, Codex or Gemini as a product client. ## Exact OAuth identity and callback checks

CyberMeters advertises fixed staging issuer `https://api-staging.cybermeters.com` and resource `https://mcp-staging.cybermeters.com/mcp`. The API code enables CIMD and optional DCR, requires S256 PKCE and the exact resource, and checks an exact `MCP_OAUTH_CIMD_ALLOWED_CLIENT_IDS` list or the guarded DCR redirect list. These are separate lists: allowing a DCR callback does not allow a CIMD client ID. Both hosted lists default to `[]`; only bounded loopback DCR registrations are usable in a short synthetic test. A client that selects CIMD by default will fail with today's empty allowlist; explicitly choose DCR where its UI/CLI allows it or add the **verified exact** CIMD URL for a controlled test. The Cloudflare OAuth SDK advertises RFC 9207 `iss` support; verify the exact issuer in successful **and error** redirects with each client before relying on stable hosted callbacks. [OpenAI OAuth requirements](https://developers.openai.com/plugins/build/auth) · [Claude OAuth requirements](https://claude.com/docs/connectors/building/authentication).

**ChatGPT-specific acceptance check:** the current gateway protects the entire MCP server and returns protected-resource metadata plus an HTTP `401 WWW-Authenticate` challenge before tool discovery; this is a legitimate server-wide OAuth path, with no known tool-metadata blocker. Its tools declare read-only annotations but no explicit per-tool `securitySchemes`. OpenAI requires `securitySchemes` and `_meta["mcp/www_authenticate"]` when triggering **tool-level** sign-in, and says omitted tool schemes inherit the server default. Test the actual private-plugin connection, sign-in, one read and reauthorization after revocation before claiming ChatGPT web support. If that client flow reveals a tool-level requirement, the pinned MCP server package must first be checked for a way to serialize the scheme; simply adding a `securitySchemes` field to the current `registerTool` config would be ignored. [OpenAI OAuth guide](https://developers.openai.com/plugins/build/auth).

For every surface advertised to customers, record account/region eligibility, the exact client ID and callback observed, OAuth consent, a real read-only tool result, cross-tenant denial, revocation and reconnect on staging. Keep production disabled until the separate [rollout gates](MCP-BETA-ROLLOUT.md) pass. A protocol simulator result is not a named-client result.
